# Contributing

ReadSync is a personal project, but fixes and suggestions are welcome. For a
security problem, follow [SECURITY.md](./SECURITY.md) instead of opening an
issue.

## Setup

You need Node **22.12 or newer**. Render and the Dockerfile pin `22.23.4`
(see `.nvmrc`). You also need a Postgres database.

```bash
cp .env.example .env      # then fill in DATABASE_URL, SESSION_SECRET, ...
npm run setup             # npm install + dev server (tsx watch src/server.ts)
```

There are two ways to get a local database:

- **Docker:** `docker compose up` starts the app (dev target) and
  `postgres:16-alpine` on `127.0.0.1:5432`. The compose file sets no
  `ADMIN_PASSWORD_HASH`, so dashboard login is off until you add one.
- **Your own:** point `DATABASE_URL` at any Postgres you control.

Either way, migrations run automatically on server start.

For the dashboard, run `npm run dev --prefix frontend` alongside the server.
It proxies `/api`, `/u`, `/health` and `/socket.io` to port 3000.

**The userscript build needs `API_KEY` and `USERSCRIPT_UPDATE_TOKEN`** in the
environment or in the root `.env`. Without them, `npm run build:all` and
`npm run verify` fail. See [docs/USERSCRIPT.md](./docs/USERSCRIPT.md).

Full env var list: [docs/DEPLOYMENT.md](./docs/DEPLOYMENT.md#environment-variables).

## Before you push

```bash
npm run verify
```

`npm run verify` runs:

- backend tests;
- `tsc --noEmit`;
- Biome;
- frontend lint, tests and build;
- the userscript build.

CI (`.github/workflows/verify.yml`) runs the same command on every push to
`main` and every pull request.

`./scripts/setup-git-hooks.sh` installs a pre-push hook that runs the backend
tests and the type check.

More on tests, including the optional database integration suite:
[docs/TESTING.md](./docs/TESTING.md).

## Conventions

- **Formatting and lint:** Biome (`biome.json`). Run `npm run format` and
  `npm run lint:fix` for the backend; the frontend has its own lint script.
- **Commits:** conventional style: `feat:`, `fix:`, `docs:`, `chore:`,
  `test:`, `refactor:`. Don't add `Co-Authored-By` lines.
- **Database access:** raw `pg` with parameterized queries. No ORM.
- **Contracts to protect:** reading progress, authentication, and the
  Socket.IO events the dashboard relies on. If a change touches the
  userscript, API and dashboard together, ship all three together.

## Adding a database migration

1. Add a new file in `src/db/migrations/` named with the next number, for
   example `021_short_name.sql`. Files run in filename order.
2. **Never edit a migration that has been applied anywhere.** Write a new
   one instead.
3. A file containing `CONCURRENTLY` runs outside a transaction and is
   recorded only after it succeeds. Keep such files to index statements that
   are safe to retry (`IF NOT EXISTS`).
4. Every other file runs in one transaction under an advisory lock, so a
   failure rolls back the whole file.
5. Add a short entry to [docs/DATABASE.md](./docs/DATABASE.md).

`npm run build` copies the SQL files into `dist/db/migrations/`. `dist/` is a
build output and is never committed.

## Build outputs

`dist/`, `public/app/` and `dist-userscript/` are generated by the build and
gitignored. Don't commit them. Render and Docker build them from source.
